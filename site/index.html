One codebase. Four platforms.

Write your UI once. The same code compiles to native SwiftUI, WinUI, Jetpack Compose, and terminal.

Counter.hx 
import mui.App;
import mui.View;
import mui.ui.*;

class Counter extends App {
    @:state var count:Int = 0;

    override function body():View {
        return new VStack([
            new Text('Count: ${count.get()}'),
            new HStack([
                new Button("-", function() count.set(count.get() - 1)),
                new Button("+", function() count.set(count.get() + 1)),
            ], 8),
        ], 10);
    }
}

Built for real apps.

Not a toy abstraction. Each component compiles to the platform's native widget with zero overhead.

⚡

Zero runtime overhead

Typedefs, subclasses, and abstracts compile away entirely. Your app runs native code, not a compatibility layer.

🔌

Type-safe bindings

Toggle, TextInput, and Slider accept @:state fields directly. @:from abstracts handle backend conversion at compile time.

🛠

Macro-powered ForEach

ForEach.build() transforms builder closures into backend-specific code. String templates for codegen backends, runtime closures for others.

🎨

Unified color & font enums

ColorValue and FontStyle map to each platform's native types via .toBackend(). One palette, four renderers.

🚀

CLI tooling

mui init, build, run. Scaffolds projects, delegates to backend CLIs, handles cross-compilation for iOS and Android.

🔧

Extensible by design

Add a new backend by adding #elseif blocks to ~25 files. Each addition is 2-5 lines of mechanical import + constructor mapping.

18 unified components.

Layout, controls, navigation, and data display. Each maps to the right native widget.

Up and running in 30 seconds.

Install mui and a backend, scaffold a project, and build.

$ haxelib git mui https://github.com/Pign/mui
$ haxelib git sui https://github.com/Pign/sui
$ haxelib run mui init MyApp
$ cd MyApp
$ mui run sui
